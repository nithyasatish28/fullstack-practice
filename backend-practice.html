Part 1 · Python conditions

Warm-up for the Checkpoint question “Validate a package”. Comparisons, the in keyword, and how return stops a function.

1.1Python

What does this print?

print(0 <= 0)

<= means “less than or equal to”, so 0 <= 0 is True. That’s why a weight check uses weight <= 0: a weight of 0 is rejected too.

1.2Python

What does this print?

statuses = ["received", "ready", "dispatched"]
print("Ready" in statuses)

in looks for an exact match, and capital letters count. "Ready" is not the same as "ready".

1.3Python

What does this print?

def check(n):
    if n <= 0:
        return "too small"
    if n > 100:
        return "too big"
    return "ok"

print(check(-1), check(150), check(50))

Each return ends the function straight away. -1 hits the first if, 150 hits the second, and 50 passes both and reaches return "ok".

1.4Python

Both checks fail here. What does this print?

def check(weight, status):
    if status != "ok":
        return "bad status"
    if weight <= 0:
        return "bad weight"
    return "fine"

print(check(0, "lost"))

The first check that fails returns, so the order of your ifs decides which message you get. If a task says “check the weight first”, put the weight check first.

1.5Python

Write is_valid_destination(city). It returns True if city is in CITIES, otherwise False.

CITIES = ["Bengaluru", "Chennai", "Mumbai"]

def is_valid_destination(city):
    # your code
    pass
Show hint

city in CITIES is already True or False, so you can return it directly.

Show solution
CITIES = ["Bengaluru", "Chennai", "Mumbai"]

def is_valid_destination(city):
    return city in CITIES

print(is_valid_destination("Chennai"))   # True
print(is_valid_destination("Delhi"))     # False

Part 2 · Python loops and dictionaries

Warm-up for the Checkpoint question “Dispatch summary”. Counting in a loop, reading values from a dict, and counting into a dict with .get().

2.1Python

What does this print?

count = 0
for n in [4, 7, 2]:
    count = count + 1
print(count)

count goes up by 1 for each item; it doesn’t add the numbers. Three items, so 3. (Adding the numbers would give 13.)

2.2Python

What does this print?

package = {"destination": "Chennai", "status": "ready"}
print(package["status"])

package["status"] looks up the key "status" and gives back its value, "ready".

2.3Python

What does this print?

statuses = ["ready", "dispatched", "received", "dispatched"]
done = 0
for s in statuses:
    if s == "dispatched":
        done = done + 1
print(done, len(statuses) - done)

done counts only the "dispatched" ones: 2. Everything else is len(statuses) - done: 4 − 2 = 2. That’s exactly how “pending” is worked out.

2.4Python

What does this print?

counts = {"Chennai": 2}
print(counts.get("Chennai", 0), counts.get("Mumbai", 0))

.get(key, default) returns the default when the key isn’t there, instead of crashing. Mumbai isn’t in the dict, so you get 0.

2.5Python

What does this print?

counts = {}
for city in ["Pune", "Goa", "Pune"]:
    counts[city] = counts.get(city, 0) + 1
print(counts)

The first time a city appears, .get gives 0, so it becomes 1. The next time it gives 1, so it becomes 2. This one line counts anything per key.

2.6Python

Write count_heavy(packages). It returns how many packages have a weight greater than 10.

def count_heavy(packages):
    # your code
    pass

print(count_heavy([{"weight": 12}, {"weight": 3}, {"weight": 10}, {"weight": 18.5}]))   # should print 2
Show hint

Start a counter at 0, loop over the packages, and add 1 when package["weight"] > 10. A weight of exactly 10 doesn’t count.

Show solution
def count_heavy(packages):
    heavy = 0
    for package in packages:
        if package["weight"] > 10:
            heavy = heavy + 1
    return heavy

print(count_heavy([{"weight": 12}, {"weight": 3}, {"weight": 10}, {"weight": 18.5}]))   # 2

Part 3 · JWT tokens

Warm-up for the Checkpoint question “Check a token's payload (JWT)”. Reading a token's payload, checking its type, and working out whether it has expired.

3.1Python

What does this print?

payload = {"username": "asha", "token_type": "refresh", "exp": 1000}
print(payload["token_type"] == "access")

This is a refresh token, so its token_type isn’t "access". Checking the type stops a refresh token being used to call normal routes.

3.2Python

A token has exp = 1000 and the time now is 1000. What does this print?

exp = 1000
now = 1000
print(now >= exp)

>= includes “equal”, so it’s True: the token has expired. A token stops working at exp, not one moment after.

3.3Python

What does this print?

def who(payload):
    if payload["token_type"] != "access":
        return None
    return payload["username"]

print(who({"username": "ravi", "token_type": "refresh"}))

The type isn’t "access", so the function returns None before it ever reaches the username.

3.4Python

Which part of a JWT can anyone read if they copy the token?

header.payload.signature

The header and payload are only encoded, not encrypted, so anyone can decode them. The signature stops people changing the payload, not reading it. Never put a password in a token.

3.5Python

Write is_expired(payload, now). It returns True if the token has expired (now is equal to or later than exp), otherwise False.

def is_expired(payload, now):
    # your code
    pass

print(is_expired({"exp": 1000}, 999))    # False
print(is_expired({"exp": 1000}, 1000))   # True
Show hint

now >= payload["exp"] is already True or False, so you can return it directly.

Show solution

print(is_expired({"exp": 1000}, 1000))   # True

Part 4 · Roles and permissions (RBAC)

Warm-up for the Checkpoint question “Roles and permissions (RBAC)”. Looking up what a role may do, handling unknown roles safely, and choosing between 401 and 403.

4.1Python

What does this print?

PERMISSIONS = {"user": ["view"], "admin": ["view", "delete"]}
print("delete" in PERMISSIONS["user"])

PERMISSIONS["user"] is ["view"], and "delete" isn’t in it. A plain user can only view.

4.2Python

What does this print?

PERMISSIONS = {"user": ["view"]}
print(PERMISSIONS.get("guest", []))

There’s no "guest" key, so .get returns the default you gave it: an empty list. PERMISSIONS["guest"] would crash with a KeyError instead.

4.3Python

What does this print?

PERMISSIONS = {"user": ["view"]}
print("view" in PERMISSIONS.get("guest", []))

An unknown role gets an empty list, and nothing is in an empty list, so the answer is False. That’s a safe way to say “not allowed” without crashing.

4.4Python

A user is logged in with a valid token, but their role isn’t allowed to delete. Which status code should the API send?

DELETE /packages/3   (role: "user")

401 means “who are you?”: no token, or a bad one. 403 means “I know who you are, but you’re not allowed.” Logging in again won’t help a 403.

4.5Python

Write is_admin(role). It returns True for "admin" and "super_admin", and False for anything else.

def is_admin(role):
    # your code
    pass

print(is_admin("admin"))         # True
print(is_admin("super_admin"))   # True
print(is_admin("user"))          # False
Show hint

Put the two allowed roles in a list and use in.

Show solution
def is_admin(role):
    return role in ["admin", "super_admin"]

print(is_admin("admin"))         # True
print(is_admin("super_admin"))   # True
print(is_admin("user"))          # False

Part 5 · Password hashing

Warm-up for the Checkpoint question “Salted password hashing”. What hashlib.sha256 gives back, why the same input always gives the same hash, and what a salt changes.

5.1Python

What does this print?

import hashlib
a = hashlib.sha256("secret".encode()).hexdigest()
b = hashlib.sha256("secret".encode()).hexdigest()
print(a == b)

A plain hash always gives the same result for the same input. That’s exactly why we add a salt: without one, two users with the same password would have the same hash.

5.2Python

Now each password gets a different salt. What does this print?

import hashlib
a = hashlib.sha256(("x1" + "secret").encode()).hexdigest()
b = hashlib.sha256(("y2" + "secret").encode()).hexdigest()
print(a == b)

The salt changes the input, so the hashes are completely different even though the password is the same. To check a login later, you hash with the same salt again.

5.3Python

How long is a SHA-256 hex digest?

import hashlib
print(len(hashlib.sha256("hi".encode()).hexdigest()))

SHA-256 always gives 64 hex characters, whether the input is “hi” or a whole book. The length of a hash tells you nothing about the password.

5.4Python

Why do we write .encode() before hashing?

hashlib.sha256("secret".encode())

hashlib works on bytes, not text. .encode() turns the string into bytes. It doesn’t encrypt or salt anything.

5.5Python

You have a stored password hash. Can you turn it back into the original password?

4634b654427463d0f90e3c364391473ede343f5d49a2ba54d3d0c45e26fe47bb

Hashing is one-way, so there’s no key and no decode. To check a login, you hash what the user typed and compare the two hashes.
